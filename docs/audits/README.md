# Audits

Point-in-time findings, kept because they record why the site is the way it is
and which claims were removed and when. They are history, not a to-do list: a
finding here may have been fixed, superseded or deliberately declined, and the
date in the filename is the date it was true.

They sat in the repository root, beside `README.md` and `PRODUCT.md`, which
made four dated snapshots look like current guidance.

| File | Date | What it covers |
|---|---|---|
| `CONTENT_AUDIT.md` | undated | Copy findings, companion to `CONTENT_STYLE_GUIDE.md` |
| `PRODUCT_DESIGN_AUDIT_2026-07-13.md` | 2026-07-13 | Product and design review |
| `MOBILE_RESPONSIVENESS_AUDIT_2026-07-14.md` | 2026-07-14 | Mobile layout review |
| `SEO_AEO_GEO_AUDIT_2026-07-29.md` | 2026-07-29 | Search and AI-answer readiness; drove the remediation plan in `docs/superpowers/plans/` |

For what actually governs new copy, read `CONTENT_STYLE_GUIDE.md`.
